# Save and Release Notes

**Who this is for.** You have a world saved by an earlier version of OpenCraft and you want to open it in this build.

**What to do first.** Make a copy of the save file and put it somewhere the game will not touch.

Loading an old world and then saving it upgrades the file to the current format. Older builds cannot open the upgraded file. The copy is your way back.

After that, load your world. Choose Load Game from the main menu, or launch straight into it with the save path. Expect the same seed, the same blocks you changed, new terrain everywhere else, and a calendar that starts at day 0. The rest of this page explains each of those.

## What changed in this release

- The world now has four biomes, a real sea level, and oceans filled with water.
- The world has a calendar: a day counter and a configurable season length.
- Seasons change surface blocks, and weather adds rain or snowfall.
- New worlds pick a safe land spawn instead of spawning at the world origin.
- The save file now carries the world's game mode (Survival or Creative), your health, hunger, and breath, and the contents of every chest you placed.
- Survival now has health, hunger, and breath, with fall, drowning, and starvation damage, regeneration, death, and respawn.
- Apples and bread restore hunger through a hold-to-eat action; apples drop from oak leaves.
- Hoes till grass and dirt into Farmland; Wheat grows through four stages and pauses in Winter; Bread is crafted from three Wheat.
- Chests hold 27 slots, and surface-ruin LootChests carry deterministic per-seed loot.
- The item vocabulary now includes leather, raw porkchop, raw beef, rotten flesh, bones, arrows, swords, and bows. An older build cannot read a save that carries them, and an older save can never contain them.
- New worlds created from the New Game screen default to Survival; Creative remains selectable there, and fresh worlds launched from the command line default to Creative.
- Old worlds keep every block you edited. Everything you never edited is regenerated by the new terrain generator.

## What a save file contains

A world save is a single file with the `.mcvx` extension, kept in the `saves/` folder next to the game's settings. The world list shows each file as a row, using the file name and the time it was last changed. A world the game cannot read stays in the list marked "(cannot load)" instead of silently disappearing.

The file stores:

- The world seed.
- Your edits: every block you broke or placed, with its position and the block that replaced the generated one.
- Crop stages, which are ordinary chunk edits. Crop growth progress is not saved.
- Your player: position, view direction, game mode, fly toggle, health, hunger, breath, selected hotbar slot, and render distance.
- Your inventory: hotbar slots, main inventory, cursor stack, and any unfinished crafting grids, which may now include leather, raw porkchop, raw beef, rotten flesh, bones, arrows, swords, and bows. An older build cannot read a save that carries them, and an older save can never contain them.
- The contents of every chest you placed, stored by position as 27 slots.
- The world clock: the time of day and the number of whole days elapsed.
- The calendar: the day index and the length of one season (stored as `day_index` and `season_length_days`).
- The live mobs: each mob's kind, feet position, facing, and remaining health, written after every chest record.

The file does not store terrain. Terrain is produced from the seed every time a chunk is needed. That is why a save is small, and it is why terrain can be regenerated on load.

Saving writes a temporary file first and then renames it over the old one. An interrupted save therefore cannot leave a half-written world; you keep the previous good file.

## Loading a save from an older version

### The calendar starts at day 0

Saves written before the calendar existed carry no day or season data. They load with:

- Day index 0.
- A season length of one game day.
- Noon, if the save is old enough to predate time-of-day storage.

Day 0 starts in the season chosen by your world seed. Different seeds start in different seasons, so an old world may resume in Spring, Summer, Autumn, or Winter. That is determined by the seed, not by the date you load it.

The calendar is stored the next time the world is saved. Use quick save, the pause menu's Save and Quit, or simply close the window.

### An older save loads as Creative

Saves written before version 6 carry no game mode and no vitals. They load as:

- Creative mode, so flying and building work as they did in the release that wrote them.
- Full health, hunger, and breath.
- No chest records, because earlier versions did not store chest contents.

The mode is chosen when a world is created and cannot be changed afterwards. A migrated world therefore keeps its Creative mode for the rest of its life, and a newer build reads it as Creative every time. The file is upgraded on the next save, as described below.

### An older save loads with no mobs

Saves written before version 7 carry no mob records. They load with an empty mob list, and the world resumes without the animals or hostiles that a version 7 save would have preserved. New mobs spawn from the world seed as usual, so the world is playable immediately; it simply starts with no persisted mobs. The mob tail is written the next time the world is saved.

### Terrain you never edited is regenerated

Only your edits are in the file. On load, the game regenerates every chunk from the seed and then reapplies your edits on top.

- Every block you changed stays changed.
- Every other block is whatever the current terrain generator produces at that position for that seed.
- This is deliberate, not a migration bug. The old terrain was never stored, so there is no copy of it to preserve.

The visible consequences for an old world:

- Familiar landmarks may be gone.
- Your base may now sit on a cliff, inside a mountain, or beside a new ocean.
- New oceans, beaches, mountains, trees, and surface ruins can appear around what you built.
- The world is still the same seed, so it is still deterministic: the same build and seed always produce the same new terrain.

If your saved position is now inside solid ground and you are in walk mode, press F to fly out, then press F again to return to walking.

### The save is upgraded when you save

On the next save, the world is written in the current format and gains the calendar fields. The current format cannot be read by older builds. If you might return to an older build, keep the copy you made first.

Loading a world does not rewrite its file by itself. The upgrade happens only when the world is next saved.

The previous release wrote save format version 6; this build writes version 7. The version 6 addition sits at the end of the file: the world's game mode, your health, hunger, and breath, and one record per chest with its position and 27 slots. A version 5 file has no such tail, which is exactly why it loads as Creative with full vitals and no chest records. A file that claims a version newer than this build understands is rejected instead of guessed at.

Version 7 appends the mobs after the last chest record: a `u32` mob count followed by one 19-byte record per mob — kind (`u8`), feet `x`/`y`/`z` (`f32` each), facing (`yaw` as `f32`), and remaining health (`u16`). Records are sorted by kind and then by position, so the same world always writes the same tail. Version 1-6 saves have no mob tail and load with no mobs. A malformed mob section fails the whole load closed: an unknown kind, a non-finite position or facing, health above the kind's maximum, a duplicate `(kind, position)` record, or an out-of-bound count is rejected rather than skipped.

A scripted demo save pins one concrete v7 layout. An edit-free save with an empty inventory is 153 bytes: the version word is at offset 4 and the mob count is at 149. The `--demo-survival` run is edit-free and its `inventory_kept=true` path keeps one Apple and one Stick, so that save is exactly 159 bytes with the v6 header at offset 144: mode at 144, health at 145, hunger at 147, air at 149, chest count at 151, and mob count at 155. The general empty-inventory v6 constants are 138, 139, 141, 143, and 145, and the general v7 mob count is at 149. The `--demo-combat` save is exactly 204 bytes: its mob count is at 162, and the two surviving hostile records occupy 166..204. That demo earns the wood sword and the pig and cow drops on the way, so the inventory section is part of the layout: the save holds the two surviving hostile records at 11 and 14 health together with the earned four inventory stacks (a wood sword, raw porkchop, raw beef, and leather). A change to what a mob drops or what the demo crafts changes the length, so the pinned numbers are measured from a real run rather than derived. Ordinary content saves are variable-length because chunk edits shift the tail. Unknown block, item, mode, chest, or mob data and water fail closed.

A damaged or unreadable save is not repaired by the game. When the game is launched directly into a world and the file cannot be read, that launch starts a new world at the same path instead of failing. Keep the copy before experimenting.

## The new terrain, briefly

The generator now builds four biomes from the seed:

- **Plains** and **Forest** share the middle height range, with grass, dirt, and oak trees. Forest is denser.
- **Mountains** rise above a fixed mountain threshold and show bare stone with snow near their peaks.
- **Ocean** is every column below the fixed sea level. Ocean basins are filled with water and have a sand seabed. Basins deepen away from the shore, so the deepest oceans hold 24 blocks of water.

Sand beaches sit where the land meets the water line. Deterministic surface ruins appear on some plains and forest land. All of this comes from the seed alone.

The old generator produced a single grassland. The current generator reads the same seed but shapes it differently, which is why an old world's unedited terrain looks new.

## Water

Water is part of world generation. It is not a normal block you can own or move.

- Every column below sea level is filled with water when its chunk is generated.
- Water is static. It does not flow, spread, or refill a hole you dig into a seabed.
- Water cannot be mined, carried, placed, or held in the hotbar. It is never an item.
- Water is never written into a save. The save format rejects water in stored edits, so a tampered file fails to load rather than producing a corrupt world.
- A generated ocean is recreated from the seed on every load, so it costs nothing in the file. You can fill individual water cells by placing blocks into them, and those placements are saved as normal edits, but there is no way to drain or remove an ocean.

You can swim in it. In walk mode, water applies drag and gravity: an idle body sinks away from the surface, and holding Jump rises back up. There is no automatic surface lock and no separate dive key. Movement is slower than on land. Fly mode behaves as it always has; water does not change it.

The water surface is translucent, and the view shifts to underwater fog while your eye is submerged.

## Spawning in a new world

A fresh world no longer spawns at the world origin. The origin can be open ocean after the terrain rewrite, so the game searches outward from it for a safe column and uses the first one it finds.

A safe column is:

- Dry land at least two blocks above sea level.
- Clear of tree trunks and overhanging leaves.
- Clear of surface ruins.

The search is bounded and deterministic. The same seed always picks the same column. In the rare case that no safe column exists within the bound, the game stops with a message naming the seed and the search radius instead of dropping you into water or inside a wall.

New worlds created from the New Game screen default to Survival: they spawn walking and cannot fly. Choose Creative on that screen to keep the previous flying and building behavior. A fresh world launched from the command line defaults to Creative; pass `--creative` or `--survival` to pick its mode (the last flag wins). A loaded world always keeps the mode it stored, so those flags do nothing to it. In Creative, press F to drop into walk mode or fly again; in Survival, F does not enable flight.

Loading an existing save never moves you. Your saved position is restored exactly, even when the regenerated terrain around it has changed.

## Seasons and weather

The calendar is a pure function of three things: the day index, the season length, and the world seed. Nothing depends on your computer's clock, so the same save always resumes in the same season and the same weather.

- Day 0 starts in the season chosen by the seed.
- A new season begins every time the day index crosses the season length.
- The New Game screen offers season lengths of 1, 2, 4, and 8 days. The default is 1 day.
- A save file can carry any season length from 1 to 365 days. A stored value outside that range is treated as 1 day instead of breaking the world.
- One game day lasts 20 real minutes at normal speed. Development flags can accelerate this, but they do not change how time is stored.

Season boundaries change how the world looks:

- **Winter** turns the grass surface of plains and forest into snow. Trees keep their trunks and branches and stand bare through the winter; they no longer disappear with the green surface.
- **Spring**, **Summer**, and **Autumn** keep the grass surface and the full canopy; trees stay green until Winter arrives.
- Leaves are the only seasonal part of a tree. Trunks and branches are generated identically in all four seasons.
- Beaches, ocean seabeds, and the altitude snow caps on mountains look the same all year.

The change is applied to chunks in a bounded wave rather than all at once, so the game keeps running while the world changes around you. Every block you edited still wins over the seasonal surface.

Weather is decided per day from the seed and the day index:

- Most days are clear.
- Spring, Summer, and Autumn days can bring rain.
- Winter days can bring snowfall, never rain.

Weather is presentation only. It never changes blocks and is never saved. Because it is derived from the seed and day, reloading a save shows the same weather for the same day.

Season length is stored in the save. A launch flag that sets season length applies only when creating a new world; a loaded world always keeps the length it stored.

## Survival, health, and death

Survival is the default for worlds created from the New Game screen. It is a real ruleset, not a label:

- The vitals are health 20, hunger 20, and breath 300. The HUD shows hearts, hunger, and air bubbles; bubbles appear while you are submerged or below full breath.
- A fall of up to 3 blocks is free. Past that, each whole block of fall distance costs 1 health.
- While your head is submerged, breath drains at 20 points per game second, so a full lung lasts 15 seconds. Once it is empty, drowning costs 2 health per game second.
- Hunger drains 1 point per 30 game seconds. At zero hunger, starvation costs 1 health per 4 game seconds.
- At hunger 18 or above, you regenerate 1 health per 4 game seconds, and each point healed costs 1 hunger.
- Creative is immune: it takes no damage, loses no hunger or breath, and keeps its flight toggle.
- The mode is chosen when the world is created and cannot be changed later.

When health reaches zero, the Death screen appears. **Respawn** restores full health, hunger, and breath at the deterministic spawn and keeps your inventory exactly as it was. **Quit** saves the world and returns to the main menu. A save file that is already at zero health opens the Death screen when loaded, so it can be resolved the same way.

## Food

- Apples drop from oak leaves deterministically: one in eight leaf blocks, decided by the world seed and the leaf's position.
- Hold Right Click with apples or bread in the selected hotbar slot to eat. A progress bar fills over 1.6 seconds. Releasing the button or moving cancels the meal without consuming the food.
- Eating is refused at full hunger with "Cannot eat while full". An apple restores 4 hunger; bread restores 6.
- Bread is crafted from three Wheat in a row at a crafting table.

## Farming

- Wood, Stone, and Iron hoes are tools with durability. Right-click the top face of a grass or dirt block to till it into Farmland; side faces are refused.
- Right-click Farmland with Wheat Seeds to plant a crop.
- Wheat has four stages, and each stage takes 60 game seconds. Winter pauses growth. Growth progress is not saved, so a reloaded crop resumes from its current stage.
- Mature wheat harvested with Left Click yields 1 Wheat and 2 Wheat Seeds. Immature wheat returns 1 Wheat Seed.
- Crop stages are ordinary chunk edits. They survive save/reload and chunk unload/regeneration.
- Bread is three Wheat in a row at a crafting table.

## Chests and ruins

- A Chest is crafted from eight Oak Planks in a ring (a 3x3 pattern with an empty center) at a crafting table.
- A chest has 27 slots; the chest screen shows them next to your 36-slot player inventory.
- The chest screen is whole-stack only. Left click moves a whole stack between the chest and your inventory; right click is inert in the chest screen. The standalone inventory panel keeps its right-click split/place-one behavior; the chest screen does not.
- E or Escape closes the chest screen.
- Contents are stored per chest position and persist across save and reload.
- Breaking a chest requires room in your 36 inventory slots for all of its contents plus the Chest item itself. If there is not enough room, the break is refused with "Not enough inventory space to break the chest" and nothing changes.
- Surface ruins can contain a LootChest. Its contents are deterministic for the world seed and the ruin, so the same save always yields the same loot. A LootChest you have emptied stays recorded as empty and never re-rolls. Breaking it yields one ordinary Chest.
- There are no item-drop entities. Blocks and crops go straight into your inventory, and death keeps your inventory.

## The menu background is a save too

The rotating scenery behind the main menu is a real world save, kept separately from your playable worlds at `saves/background/background.mcvx`. It uses the same format as any other save: seed, your block edits, position, inventory, clock, and calendar.

- **Edit Background** on the main menu enters that world as a normal gameplay session. Build, mine, and fly with the usual controls, then use the pause menu's Save and Quit.
- The menu camera sits at the saved player's eye position, so the menu looks out from the spot where you left the editor. The sideways drift and fixed downward tilt are unchanged; the saved view direction is not used.
- The menu sky follows that save's time of day, and the menu terrain follows its calendar season. Both are frozen while you sit on the menu; they advance only while you are editing. Weather stays clear on the menu.
- The file lives in a subdirectory of `saves/`, so it never appears in the Load Game list and cannot be deleted from there. No background path ever writes a playable world's save.
- If the file is missing, the built-in deterministic scenery appears and nothing is written until your first edit. If the file is unreadable, the built-in scenery appears with a message on the main menu and the file is left untouched; editing the background then saves over that unreadable file the next time you use Save and Quit.
- To reset the background, delete `saves/background/background.mcvx`. The next launch shows the built-in scenery; the next successful edit creates a fresh file.
- If a background save fails while editing, the editor stays open with the reason on the pause screen so the work is not silently lost. Closing the window while editing saves the background like any other gameplay session.

Edit Background always runs Creative rules without rewriting the stored mode. There is no creative inventory just for the background, so bring blocks from a world or mine what is there.

## What did not change

These guarantees survived the terrain rewrite:

- **The seed still determines everything.** The same build, seed, and calendar always generate the same terrain, trees, ruins, caves, ores, and water.
- **Trees render in full, including near the shoreline.** A tree whose trunk, branches, or canopy cross a vertical chunk edge keeps every block, so trees are never cut short halfway up a slope. A tree standing on a steep bank can still have its lower leaves hidden by the hillside in front of it, which is ordinary terrain occlusion rather than clipping.
- **Your edits always win.** They are reapplied over freshly generated terrain when a chunk loads, unloads, or changes season.
- **Caves still carve stone only below the surface.** They never open the surface or remove the ground you stand on.
- **Ores still appear only in their depth bands**, in stone, as before.
- **Bedrock still forms the bottom of the world.** You cannot fall out of it.
- **The save is still one atomic file**, and player state and inventory from the previous release load without loss.

## Checklist after loading your old world

1. Make the backup copy before you load, if you have not already.
2. Load the world and note which season day 0 gives you.
3. Save once (quick save, Save and Quit, or close the window) to write the calendar into the file.
4. Survey your builds. Your edited blocks should be exactly where you left them; the terrain around them may be new.
5. If you are stuck inside blocks, press F and fly out.
6. Check your inventory, hotbar, and any unfinished crafting grids. They load as before.
7. Look around for new oceans and beaches if you want to try swimming.
8. If the result is not what you want, replace the world's file with the copy you made. There is no in-game undo for terrain regeneration.

## Limits and fine print

- There is no terrain migration tool. The saves-only-edits design means there is nothing to migrate: the old terrain was never in the file.
- Saves that predate the expanded inventory keep their hotbar contents; the newer inventory slots start empty. A save old enough to predate hotbar storage keeps no items.
- A save with an out-of-range render distance is rejected rather than guessed at.
- Hand-editing a save file is not supported. Corrupt or unknown data either fails the load with a named error or falls back to a safe default, depending on the field.
- The menu background's viewpoint is wherever you stood when you last saved the editor. Building across that spot can put geometry in front of or around the camera; move before saving to reframe it.
- Development flags for demos and smoke tests (`--new`, `--seed`, `--save`, `--time-scale`, `--season-length`, `--demo-days`, `--demo-swim`, `--demo-survival`, `--demo-content`, `--demo-combat`) are not part of the normal player flow. They change how a launch runs (some demos advance the calendar and save before exiting), not how an existing save file is interpreted. `--demo-survival` and `--demo-content` are bounded scripted demo switches that save and exit for the smokes. `--creative` and `--survival` select the mode of a fresh world only (the last flag wins); a loaded world keeps its stored mode.
- There are no item-drop entities and no death drops; death keeps your inventory. There is no creative inventory palette. Chest overflow is refused rather than dropping items. Crop growth progress is ephemeral and is not saved. There is no saturation, and no water or fertilizer farming.
