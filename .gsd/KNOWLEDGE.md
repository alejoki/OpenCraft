## Patterns

| # | Pattern | Where | Notes |
|---|---------|-------|-------|
| P001 | Per-field TOML fallback in src/settings/mod.rs requires a two-phase parse: first `toml::from_str::<toml::Value>` into a generic tree, then independent per-field extraction with type/range checks. Plain `#[serde(default)]` derive cannot be used for loading — serde aborts the whole struct on any field type error, losing valid siblings. Add new settings fields by extending the phase-2 lookups (see load_keybind_action / load_clamped_f32 / load_bool helpers). | — | — |
| P002 | Settings persistence (src/settings/mod.rs) uses a private Serialize-only mirror struct (SettingsToml/KeybindsToml/MouseToml/VideoToml, serde derive with Serialize only, never Deserialize) plus atomic write (create_dir_all on parent, write to <name>.toml.tmp sibling, sync_all, fs::rename over target). Loading deliberately bypasses serde (see P001 two-phase parse). When adding a settings field: extend BOTH the phase-2 lookups in load_with_warnings and the save mirror, and keep the round-trip test (save -> load_with_warnings == original, zero warnings) as the guard locking the two halves together. A KeyCode lacking a key_to_string mapping is treated as a save-time bug: panic with the action name, guarded by tests. | — | — |
| P003 | src/ui quad rendering (M001-S03) reuses the existing OverlayVertex { clip_pos: [f32;4], color: [f32;4] } + pass-through WGSL pattern with a TriangleList pipeline, depth_stencil None, alpha blend: quads are specified in physical pixels (top-left origin, y down) and converted to NDC on the CPU (x_ndc = 2x/w − 1, y flipped: y_ndc = 1 − 2y/h), emitting 6 vertices per quad (0,1,2, 2,3,0 expanded — no shared index buffer). Same pixel space as ctx.config, cosmic-text buffers, and the cursor_pos plumbing, so S04 hover hit-testing works in px with no scale-factor math at scale 1. | — | — |
| P004 | S04's settings menu consumes the pixel-space quad API from src/ui/quad.rs: build a `Quad { x, y, w, h, color }` list in physical pixels (top-left origin, y down), call `UiRenderer::set_quads(&device, &quads, surface_w, surface_h)` once per frame before render_frame, and quads draw first in the UI pass (before glyphon text) via UiPass. NDC conversion (with y-flip: y_ndc = 1 − 2y/h) is CPU-side in quads_to_vertices; pipelines in the UI pass must use depth_stencil None (color-only pass, LoadOp::Load). | — | — |
| P005 | In src/main.rs (S04-T02), `window_event` destructures `let (Some(gpu), Some(window)) = (self.gpu.as_mut(), self.window.as_ref())` at fn top, so whole-`self` methods conflict with those live field borrows: (1) `&mut self` methods like `menu_click` can only be called in match arms where gpu/window are dead first — copy dims (`gpu.ctx.config.width/height`) and clone the `Arc<Window>` before the call; (2) pure per-frame helpers like `compose_menu_text` must be free functions taking `(&Settings, &SettingsMenu)` field references, not `&self` methods — an immutable whole-`self` borrow conflicts with the live `&mut self.gpu` even read-only. Field-disjoint accesses (`self.menu.tick()`, `&self.settings`) are always fine. | — | — |
| P006 | src/main.rs KeyboardInput routing order (M001/S04-T03): while the menu is open, every key routes to the menu FIRST and returns before the gameplay match (a capture candidate must never reach InputState). With the menu closed, non-rebindable utility keys (Escape, KeyF, F5, brackets, digits) are matched BEFORE the 7 rebindable gameplay routes (single `_` arm calling apply_gameplay_key). This order is deliberate: Escape is itself a valid rebind target, so utility-first guarantees Escape always toggles the menu and F/F5/digits keep hardcoded behavior even if a gameplay action is rebound onto them. Duplicate bindings in a hand-edited settings file resolve by first-match priority in Keybinds declaration order. | — | — |
| P007 | Change-gated text shaping (M001/S03): re-shape glyphon/cosmic-text Buffers only when the text string actually changes (stats overlay at a 0.25 s cadence; set_text ~0.1–1.3 ms), never per frame; re-set_size on resize so text never stretches. Same gating applies to menu text — shape only when the composed string changes. | — | — |
| P008 | Pure immediate-mode menu module (M001/S04, src/ui/menu.rs): state machine + row layout + half-open hit-test + decisions as pure CPU logic with a caller-owned tick counter for message expiry (no clock inside the module), unit-tested before wiring (24 tests). Layout is derived per frame from ctx.config.width/height with no cached rects, so Resized/fullscreen reflow needs no invalidation path. | — | — |
| P009 | Change-gated atomic persistence (M001/S04): write settings atomically (tmp sibling + rename) once per accepted human-paced change — never per frame — plus one final save on CloseRequested; save errors surface as in-menu messages rather than being swallowed (the exiting-process CloseRequested save ignores errors by design, documented in code). | — | — |
| P010 | Bounded GUI smoke harness pattern (M001, scripts/launch_smoke.sh + scripts/settings_smoke.sh): run the game under timeout(1) with the Wayland display env attached, assert exit 124 (killed by timeout, not early exit/panic) and no panic text in captured output; settings_smoke additionally runs in a temp cwd seeded with a settings.toml and asserts the file survives byte-identical (the game must not rewrite an unchanged file). Cheap, reusable proof a GPU game actually runs headless-agent-side. | — | — |

## Lessons Learned

| # | What Happened | Root Cause | Fix | Scope |
|---|--------------|------------|-----|-------|
| L001 | winit 0.30.13's ApplicationHandler trait methods take `&ActiveEventLoop` (not `&dyn ActiveEventLoop`); `EventLoop::set_control_flow(ControlFlow::Poll)` is called once before `run_app`, window creation moves into `resumed()` via `event_loop.create_window(Window::default_attributes()...)`, and the migrated `GameApp`/`Ready` struct pattern lives in src/main.rs of the M001 worktree (S03/S04 build on this loop; window+GPU stack is behind `Option`, guarded idempotently in resumed()). | — | — | project |
| L002 | The workspace has ~12 pre-existing clippy lib warnings (needless_range_loop etc. in src/mesh/greedy.rs, src/mesh/quad.rs, src/world/manager.rs, src/world/terrain.rs) that predate M001-S01; the bin target (src/main.rs) is clippy-clean. Downstream slice verification should not treat these lib lints as a regression — scope clippy checks to the files the slice touched, or record the inherited findings as known limitations. | — | — | project |
| L003 | In this wgpu 0.19 project, glyphon 0.5.0's `render<'pass>(&'pass self, atlas: &'pass TextAtlas, pass: &mut RenderPass<'pass>)` cannot be driven through a `dyn FnMut(&mut wgpu::RenderPass)` closure hook: wgpu 0.19's RenderPass carries a lifetime and the higher-ranked closure forces the captured atlas/renderer borrows to be 'static (E0521/E0502). The working pattern is a trait with a lifetime-typed method: `trait UiPass { fn draw_ui<'pass>(&'pass self, pass: &mut wgpu::RenderPass<'pass>); }` implemented on the owner of the glyphon stack, passed as `Option<&dyn UiPass>` to render_frame. Also: glyphon 0.5.0's ColorMode has only `Accurate`/`Web` variants (no `Color`), and cosmic-text 0.10's Buffer methods (set_size/set_text/shape_until_scroll) all take `&mut FontSystem` first. | — | — | minecraft-clone |
| L004 | winit 0.30 WindowEvent::CursorLeft (and the other cursor variants like CursorEntered) carry a device_id field — matching them bare (`WindowEvent::CursorLeft => ...`) fails E0533; match with `..` (e.g. `WindowEvent::CursorLeft { .. }`). CursorMoved delivers PhysicalPosition<f64>, cast to f32 for the px-space UI (ctx.config / cosmic-text / quad renderer all share physical px at scale 1). Relevant when S04 adds menu hover/click routing. | — | — | project |
| L005 | As of M001-S03 closeout, the inherited clippy lib-warning inventory is 13 unique warnings: 6 in src/mesh/* (greedy.rs 5, quad.rs 1), 6 in src/world/* (terrain.rs 4, manager.rs 1, persistence.rs 1), and 1 in src/render/texture.rs — the texture.rs warning is NOT listed in MEM007's mesh/world scope, so slice-touched scoping must not treat any src/render pre-existing warning as a regression unless the slice touched that same file. Slice-touched files (src/ui/*, src/render/pipeline.rs, src/main.rs) are clippy-clean after S03. | — | — | project |
| L006 | In src/main.rs (M001-S04), the whole-`&mut self` `menu_click` cannot touch the RenderContext (the `gpu`/`window` field borrows from the window_event destructure — P005). Rows needing live GPU/surface effects are split: fullscreen/FOV apply inside menu_click (window is passed in, camera is a self field), while vsync's present-mode swap + surface.configure runs in the MouseInput caller, which pre-hit-tests the clicked row BEFORE the menu_click call and re-borrows `self.gpu.as_mut()` after it. `save_settings_or_warn` is deliberately a free fn with disjoint (menu, settings) args so all save sites work under live field borrows. | — | — | project |
| L007 | Rebind validation order (M001/S04, evaluate_rebind_candidate): check RejectUnsupported BEFORE the duplicate check — settings save() panics on unmapped KeyCodes, so validating key support first prevents a panic path at accept time; the duplicate rejection then names the conflicting action, consistent with validate_keybinds. | — | — | M001 |
