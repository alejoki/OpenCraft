## Edge cases

- glyphon prepare error on a frame: the UI pass is silently skipped for that frame (log-free per D006); world rendering and gameplay continue unaffected.
- Degenerate surface dims (zero width/height): quad vertex conversion avoids division by zero (unit tested).
- Cursor entering/leaving the window: cursor_pos set/cleared; no visible behavior change in S03 (plumbing only — S04 adds consumers).
- Overlay text changed only at the 0.25 s cadence: set_text/shape_until_scroll not run per frame (avoids the ~0.1–1.3 ms per-call shape cost).

## Operational Readiness

- **Health signal**: the game launches and runs with the stats overlay visible on screen (FPS/position readout over a translucent panel) — the overlay itself is the slice's on-screen observability surface (per D006 the crate deliberately has no logging dependency). The automated proxy is `bash scripts/launch_smoke.sh` passing (10 s bounded run, exit 124, no panic).
- **Failure signal**: a panic or immediate non-124 exit in the smoke run (render-loop regression), or the window/overlay failing to appear — no automated alerting exists; a human or the smoke script notices. Warnings are surfaced as returned data (S02 pattern), not logs.
- **Recovery**: `cargo build && cargo test && bash scripts/launch_smoke.sh` re-establishes a known-good state; the UI pass is additive to the world pass (D007 seam), so disabling the ui_pass argument restores the pre-S03 render path for triage.
- **Monitoring gaps**: no screenshot-level check that text is actually legible — that remains NEEDS-HUMAN (visual checks above). No runtime metrics/log stream exists by design; if the game crashes only during real interaction (not within the 10 s smoke window), the smoke script will not catch it.
