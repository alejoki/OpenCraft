# S02: Settings core with TOML persistence and tests

**Milestone:** M001
**Slice:** S02

**Goal:** Deliver a pure-logic settings layer for M001: a new src/settings module (serde + toml, no GPU and no winit event-loop dependency beyond the plain KeyCode enum) that loads and saves player preferences — 7 keybinds (forward, backward, left, right, jump_or_up, crouch_or_down, sprint), mouse sensitivity, FOV, fullscreen, vsync — to a TOML file with per-field fallback so a bad or missing settings.toml never blocks launch. Range values are clamped with warnings rather than rejected; load warnings and duplicate-keybind conflicts are returned as structured data (no logging framework this slice). Defaults must equal today's hardcoded values (sensitivity 0.0022 in src/main.rs device_event, FOV 75.0 in src/player/camera.rs Camera::new, ShiftLeft crouch / ControlLeft sprint in src/main.rs, vsync false matching the Immediate>Mailbox>Fifo preference in src/render/context.rs) so the S04 wiring swap is behavior-neutral. Everything is provable with cargo test — no GPU required.
**Demo:** After this: cargo test passes for settings round-trip (load → save → load equality), missing file → defaults, corrupt file → per-field fallback with valid fields kept, unknown keys ignored, and duplicate-keybind rejection — pure logic, no GPU required.

## Must-Haves

- cargo test is green with settings coverage proving: (1) round-trip — save then load yields identical Settings (temp dir, f32 fields exact); (2) missing file -> defaults plus warning, no panic; (3) syntactically invalid TOML -> all defaults plus warning; (4) per-field fallback — an invalid field's valid siblings are kept (e.g. bad fov, good keybinds and sensitivity survive); (5) unknown keys/sections are ignored; (6) out-of-range fov (30-120) and sensitivity (0.0001-0.01) are clamped with warnings, not rejected; (7) duplicate keybind strings in the file load successfully (never block launch) and validate_keybinds reports the conflict as data; (8) defaults equal today's hardcoded values (0.0022 sensitivity, 75.0 fov, KeyW/KeyS/KeyA/KeyD/Space/ShiftLeft/ControlLeft, fullscreen=false, vsync=false); (9) save is atomic (tmp file + rename) and creates parent directories. Additionally cargo build is clean and the module has no GPU/event-loop dependency beyond the KeyCode enum.

## Proof Level

- This slice proves: contract

## Integration Closure

S02 provides the Settings module API that S04 consumes and wires into the running game: sensitivity in the main.rs MouseMotion arm, fov_degrees in Camera construction, vsync in present-mode selection, fullscreen via the window, and keybinds routed through the Settings map. S02 itself does not modify main.rs, camera.rs, or context.rs (wiring is S04 territory). S02 depends on nothing upstream: KeyCode is a plain enum identical across winit 0.29/0.30, so the module compiles and tests pass against the already-migrated 0.30 tree. The keybind string conversion (keybind.rs) decouples the file format from any future winit bump per decision D003.

## Verification

- Decision-point data is returned by value, not logged: load_with_warnings returns a Vec of SettingsWarning (field name + reason) and validate_keybinds returns Vec of KeybindConflict (colliding action names + key) so S04 can display which field fell back and why, and reject duplicate rebinds in the menu. No log/tracing dependency is added in this slice.
