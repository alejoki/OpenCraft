## Edge cases

- Missing/corrupt settings.toml: defaults load with per-field warnings; launch never blocks; warnings surface as the menu's first-open message (S02 tests + launch smoke with no settings.toml).
- Save io::Error (permissions/disk full): surfaced as an in-menu message, never swallowed, never fatal; the atomic tmp+rename write means a crash mid-save leaves the previous settings.toml intact.
- Click with cursor outside the window (None cursor position) or on empty panel space: no-op — gameplay raycast and re-grab unreachable while the menu is open.
- Half-held movement key when opening the menu: InputState::reset clears it; re-grab on close prevents stuck keys.
- Duplicate bindings in a hand-edited settings.toml: loads with a warning (never blocks), resolves deterministically first-match in declaration order (unit-tested).
- Wayland with vsync=false: PresentMode::Immediate may be unsupported — documented accepted visual no-op (compositor fallback), Fifo (vsync=true) always supported.
- ControlFlow::Poll above 60 fps: message expiry bounded at ~60 ticks/s so warnings last ~10 s regardless of frame rate.

- **Failure signal**: a smoke script fails loudly on any non-124 exit code, panic/backtrace text in output, or a missing/changed settings.toml — it prints captured output and exits non-zero. At runtime, a save failure appears as a "could not save settings: …" in-menu message rather than being swallowed; a missing/corrupt settings.toml degrades to defaults + warnings and never blocks launch.
- **Recovery**: delete or hand-repair settings.toml → next launch loads defaults (or valid fields) with warnings shown in the menu. Re-run the gate suite (`cargo build && cargo test && cargo clippy && bash scripts/launch_smoke.sh && bash scripts/settings_smoke.sh`) to re-establish a known-good state. Atomic save (tmp sibling + rename) means a crash mid-write leaves the previous settings.toml intact.
- **Monitoring gaps**: no automated screenshot or synthetic-input test — interactive press-to-rebind, menu legibility, visible live-apply, and interactive restart persistence are NEEDS-HUMAN (section above); the smokes only cover a headless 10 s window, so interaction-only crashes would not be caught. No log stream or metrics exists by design (D006); failure visibility is entirely in-menu plus the smoke scripts.
